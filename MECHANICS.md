# SnackStudio mechanics

This is an implementation record, not a claim that the full award brief is complete. Original vector files, WORK.md, ESSAYS.md, recipient records, commissioned sound recordings, and physical production footage were not attached. PNG originals are preserved; WebP copies are used for delivery. The current release is a review build on a separate Vercel project. snackstud.io currently belongs to the existing snack-client application.

## Shared constants and storage

- Display palette: #EC4899, #DB2777, #F472B6, #FDF2F8, #111827, #FFFFFF, #FAFAFA, #F3F4F6. Supplied marks retain their original pixel colors.
- Cookie coordinates: 1254 × 1254. Six bites. Default radii: 310, 320, 350, 380, 420, 590 source units.
- Spring: 0.48 seconds, GSAP back overshoot 1.7. Flick return: 0.7 seconds. Sweep: 0.55 seconds.
- Matter gravity: 0.65; restitution: 0.52; friction: 0.12; fixed bottom collision surface. Sleeping enabled. Frame delta capped at 32 ms. Pixel ratio capped at 2.
- Storage key `snack-cookie`, schema version 1. Validated before loading. Up to 400 crumbs, evict oldest. Missing/denied browser storage falls back to memory.
- BroadcastChannel `snackstudio-cookie` and storage events. Web Locks serialize bite mutations where available. Other simultaneous mutations use revision ordering and can still race.
- Local midnight uses the device date. Shared jar day uses America/Los_Angeles. Anonymous service records expire after at most 48 hours; ghost list expires after 60 seconds. No names, camera frames, face landmarks, questions, or IPs are sent to the shared service.

## External release dependencies

1. Supply the four vector masters, WORK.md, ESSAYS.md, 50 recipient records, physical bite scans, and commissioned recordings.
2. Finish the gaps above, particularly actual-cookie bite measurement and production shared-state verification.
3. Run real-device camera/orientation checks, assistive-technology review, and performance checks on the target phone. Local Lighthouse is evidence, not a hardware guarantee.
4. Decide when the existing snack-client production domain should be replaced. This build does not move that domain automatically.
5. The implementation is delivered in an integration PR. The requested 25 mechanic-specific PRs and 25 per-PR Lighthouse/GIF packages have not been produced. Do not describe that requirement as fulfilled.
6. Video cuts are screen demonstrations of this review build. They are not final award films containing commissioned sound or the physical run.
